# Data 독립 발굴과 운영 점검

## 독립 발굴

DISCOVERY_ENABLED=true이면 Data scheduler가 Spring 요청 없이 새 상품을 검색·등록한다. 기존5분 갱신 루프에 추가되며 다음 실행 시각이 된 경우만 발굴한다. 기본 발굴 간격은1800초, 회차당 최대4개 검색이다. API 요청이나 크롤링 동안 DB 트랜잭션을 유지하지 않는다.

컬리·올리브영·무신사·11번가의 분야별16개 키워드, 총64개를 플랫폼 교차 순서로 순환한다. 각 플랫폼에 적합한 식품·뷰티·패션·생활/전자 키워드를 사용한다. 한 바퀴마다 검색 상한을20→40→60→80→100으로 늘린다.100개 이후에는 같은 범위를 주기적으로 갱신하며 전체 쇼핑몰 무제한 탐색을 의미하지 않는다. 네이버·오늘의집 등 브라우저 플랫폼의 기존 등록 상품 갱신과 수동 시드는 유지한다.

발굴 순환 위치·다음 실행 시각·lease·마지막 회차 집계는 discovery_state 테이블에 저장한다. 재시작 후 같은 위치부터 이어가고, 다른 프로세스는 유효한 lease를 가진 검색을 중복 실행하지 않는다. 저장 전에도 소유권을 확인해 만료된 프로세스의 늦은 응답을 버린다. 실패/시간 초과 키워드는 위치를 전진시켜 다른 몰을 막지 않으며 다음 순환 때 다시 확인한다.

수집 pending이20건 이상이거나 AI queued/running이100건 이상이면 발굴을 쉬고5분마다 재확인한다. 각 검색은 기본 큐20건을4개 검색에 나눈 최대5건의 예약 자리를 사용한다. 결과의 다른 신규 상품도 DB에 등록하며 기존 갱신 스케줄러가 뒤이어 예약한다. 검색 요청·발굴·갱신은 같은 advisory lock으로 큐 상한을 지킨다. 기존 상세를 제한된 검색 정보로 덮지 않는다.

설정은 .env.example의 DISCOVERY_*를 따른다. 로컬/테스트 기본 비활성이다. 운영에서는 명시적으로 활성화하며 검색·브라우저 차단을 우회하지 않는다. 공용 Product/Review 계약은 변경하지 않는다.

## 상태 확인

서버에서 다음 명령으로 JSON 집계를 확인한다.

```bash
cd /home/deploy/review-data
docker compose exec -T api crawler status
watch -n 10 'docker compose exec -T api crawler status'
```

queues.collection/analysis의 waiting/running은 전체 대기·진행 건수다. expired_leases는 만료된 running, exhausted_leases는 만료됐고 최대시도를 소진한 작업이다. 기존 워커가 만료 lease를 회수하고, 소진 작업을 실패로 정리한다. 최신 상품별 분석 상태는 latest_analysis다. 과거 stale/실패 이력과 현재 장애를 혼동하지 않는다.

empty_products는 실제 DB 리뷰가0건인 상품의 원인을 구분한다. pending/running은 수집 대기/진행, collection_failed는 최신 리뷰 수집 실패, not_collected는 미수집, collected_empty는 리뷰 수집 성공으로 기록됐지만 본문 리뷰0건인 경우다. advertised_positive는 쇼핑몰 표시 리뷰수가 양수인 상품 수다. 별점만 있는 후기·비공개·원본 응답 범위가 다를 수 있으므로 collected_empty를 시장에 리뷰가 전혀 없다는 뜻으로 단정하지 않는다.

latest_collection_failures는 상품과 리뷰의 성공/실패를 분리한 최신 집계다. discovery에는 순환 위치·다음 실행·lease·최근 등록/예약/실패수가 나온다. 토큰·작성자·본문·원본 오류 메시지는 출력하지 않는다.

## 실제 실패 조치

올리브영 A000000162179에서 PostgreSQL이 저장할 수 없는 NUL 문자 때문에 리뷰 배치 전체가 실패했다. content/author/option/images의 NUL을 저장 전에 제거한다. 제거 후 본문이 비어 있는 항목은 저장하지 않고 다른 유효 리뷰는 저장한다. 원본 ID와 중복 통합 정책은 유지한다.

없는 테스트 상품의404는 정상 데이터로 만들거나 무한 재시도하지 않는다. 네이버 응답 미수신과 일시적 ReadError는 기존 시간 상한·실패6시간 대기 정책을 유지한다. 성공0건 상품은 목록에서 제외하되 DB에 남겨 다음 정상 주기에 갱신한다.

## 실제 표본 검증

운영 무신사858911의 원본 리뷰800건을 수집했다. 대표 리뷰800건에서500건을 선택해 운영 분석 작업2301을 예약했다. 별점 원본/표본 분포는0점6/4,1점4/2,2점1/1,3점11/7,4점91/57,5점687/429다. 최저0점과 최고5점이 포함되며 선택 합계는500건이다. 실제 SSE 완료·저장·API 범위 검증 결과는 validation 문서에 기록한다. 비선택300건의 점수를 만들지 않는다.
