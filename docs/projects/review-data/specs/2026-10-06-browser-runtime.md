# 직접 수집 API 브라우저 실행 안정화

## 문제

API와 워커는 같은 이미지를 쓰지만 가상 화면(Xvfb)은 워커에서만 실행한다.
화면 모드가 필요한 오늘의집·네이버 collector를 API에서 직접 실행하면 브라우저를
시작할 수 없다. 미지원 검색도 collector 진입 시 브라우저를 먼저 실행해 501 대신
500으로 응답할 수 있다.

에이블리 검색에는 네이버 웹 검색 API 키가 필요하다. 서버의 키 누락은 별도 운영 설정
문제다. G마켓의 검색 실패는 Cloudflare의 HTTP 403 차단으로 재현됐다.
플랫폼 차단을 우회하지 않는다.

## 변경

- API에도 Xvfb와 DISPLAY를 제공한다. Chromium 공유 메모리와 메모리 한도를 조정한다.
- 브라우저는 최초 페이지 요청에서 실행한다. HTTP만 사용하는 검색과 미지원 기능에
  불필요한 브라우저를 띄우지 않는다.
- setup, 페이지 생성, 종료 중 예외가 발생해도 HTTP 클라이언트·브라우저·Playwright·
  컨텍스트를 정리한다. 정리 오류가 원래 요청 오류를 덮지 않도록 한다.
- 브라우저 실행 실패를 식별 가능한 수집 오류로 응답한다.
- 옥션 검색·상품·리뷰는 페이지 이동 직후 HTTP 403 또는 명확한 차단 화면을 확인하면
  selector 대기와 후속 리뷰 요청 없이 즉시 실패한다. 콘텐츠 타임아웃을 차단으로 단정하지 않는다.
- 키가 준비되면 네이버 API 키를 값 출력 없이 서버에 등록하고 API/워커 설정을 갱신한다.
- CAPTCHA나 Cloudflare 차단이 확인되면 실패로 기록하고 멈춘다.

## 검증과 배포

리소스 정리·지연 실행·HTTP 오류 응답·옥션 차단을 목 테스트 58개로 확인한다.
CI에서 PostgreSQL 통합 테스트와 Docker 빌드를 확인하고 develop과 main에 순서대로 반영한다.
배포 후 운영 컨테이너 상태, DISPLAY/Xvfb, Chromium 기동, 검색 응답을 확인한다.
상품·리뷰 공용 모델과 DB 스키마는 변경하지 않는다.
