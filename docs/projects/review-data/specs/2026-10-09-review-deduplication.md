# 리뷰 중복 통합·목록 제외·수집 범위

## 중복 기준과 원본 보존

같은 platform/product_id에서 본문·별점·작성자·작성일·구매 옵션·이미지가 모두 완전히 같은 리뷰를 한 그룹으로 취급한다. 작성자와 작성일이 모두 존재해야 하며 공백 작성자는 근거 없는 것으로 처리한다. 작성자·작성일이 없거나 다른 리뷰, 본문만 같은 리뷰, 다른 상품·플랫폼의 리뷰는 합치지 않는다. 별점 NULL과0도 구분한다. 문구 유사도나 감정 점수로 합치지 않는다.

서로 다른 원본 review_id의 DB 행은 삭제하지 않는다. 반복 구매나 원본 데이터 문제를 나중에 확인할 수 있도록 원본 행과 과거 분석 결과를 보존한다. 그룹에서 first_collected_at이 가장 이른 행을 대표로 선택하고 같은 시각이면 review_id 순으로 선택한다. 이후 더 작은 ID가 추가돼도 기존 대표가 유지된다. 대표의 정보가 바뀌어 그룹이 달라지면 다음 조회·분석에 변경을 반영한다.

동일 배치에 동일 review_id가 여러 번 들어오면 마지막 관측값으로 한 번만 upsert한다. PostgreSQL의 동일 행 반복 갱신 오류로 상품 전체 저장이 실패하는 일을 막는다.

## 조회와 AI 분석

리뷰 cursor 페이지와 리뷰 SSE, 분석 입력 스냅샷에 같은 대표 집합을 적용한다. 중복 통합을 먼저 수행하고 그 뒤에 페이지 cursor를 적용하므로 대표가 앞 페이지에 있다고 뒷 페이지에 다른 중복 ID가 나타나지 않는다.

AI는 대표 리뷰만 받는다. 500건 초과 시 기존 별점 분포·최고/최저·시점 분산 정책을 대표 집합에 적용한다. source_review_count는 중복 통합 후 대표 집합의 크기이고 review_count는 실제 선택·분석한 대표 건수다. 플랫폼의 광고 리뷰 수나 원본 DB 행 수와 다를 수 있다. 원본 DB 행 수는 SELECT count(*) FROM reviews로 별도 확인한다.

새 중복 ID만 추가돼 대표 스냅샷이 같으면 기존 분석을 재사용한다. 기존에 중복을 포함했던 작업은 새 입력 해시가 달라지므로 다음 수집이나 analysis-backfill에서 stale 처리하고 대표 집합으로 재분석한다. 이미 완료된 과거 결과를 새 점수처럼 합산하지 않는다. 재시도는 기존 작업의 고정 스냅샷을 사용한다.

## 리뷰 없는 상품 제외

GET /api/v1/catalog는 실제 reviews 행이 존재하는 상품만 반환한다. advertised review_count가 양수더라도 DB에 리뷰가 없으면 제외한다. 리뷰가 있지만 분석 전인 상품은 포함한다.

GET /{platform}/search는 모든 발견 상품을 등록·수집 예약한 뒤 실제 저장 리뷰가 있는 상품만 반환한다. 처음 발견한 상품은 첫 검색 결과가 비어 있을 수 있으며 리뷰 저장 후 다시 검색하면 노출된다. 수집 대상 상품을 DB에서 삭제하거나 스케줄러에서 제외하지 않는다. 기존 Spring 캐시에 이미 저장된 상품을 제거하는 기능은 이 Data 변경에 포함되지 않는다.

## 수집량과 신규 발굴 구조

HTTP 기반 워커의 REVIEW_COLLECT_LIMIT 기본값은200, 브라우저 기반 BROWSER_REVIEW_COLLECT_LIMIT는50이다. 각각1~1000으로 설정할 수 있다. AI_MAX_REVIEWS=500은 별도 분석 상한이다. 수집량을 늘려도 AI 요청당500건을 넘기지 않는다. 실제 저장량은 플랫폼이 제공한 리뷰·페이지 및 수집 성공 여부에 따라 다르다.

신규 발굴은 Spring HomeCatalogRefresher의 기동 시 및6시간 주기 키워드 검색이다. Data는 검색 결과를 등록하고 pending20건 상한 안에서 수집을 예약한다. Data5분 스케줄러는 DB 등록 상품을 갱신하며 상한 밖에서 등록만 된 상품도 나중에 예약한다. Data 스케줄러가 독립적으로 쇼핑몰 전체를 탐색하는 구조는 아니다.

고정26개 키워드·몰당3건의 상위 결과는 시간이 지나면 같은 상품을 반복한다. 신규 발굴을 지속적으로 늘리려면 담당팀에서 검색 키워드 순환·카테고리/페이지 범위를 확장하거나 기존 crawler seed --file seeds.toml을 사용해 Data에 별도 시드를 보충할 수 있다. 브라우저·차단 플랫폼의 검색을 자동으로 우회하지 않는다.
