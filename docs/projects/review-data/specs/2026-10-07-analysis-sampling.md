# 자동 분석과 별점 분포 대표 표본

## 정책

사용자 요청에 따라 자동 분석을 활성화한다. 저장 리뷰가500건 이하면 전체를 분석한다.
초과하면 하나의 요청에 최대500건의 별점 분포 대표 표본을 보낸다. AI v0.5 본문은 유지한다.
별점은 원본 플랫폼 별점(5점 환산)이며 아직 계산되지 않은 RTI로 선택하지 않는다.

별점 구간은0, (0,1], (1,2], (2,3], (3,4], (4,5], 별점 미제공으로 나눈다.
구간별 원본 건수에 비례한 할당을 사용하고 소수 잔여를 분배해 정확히 상한만큼 선택한다.
극소수 구간도 한 건 이상 보존하고 실제 최고·최저 별점 리뷰를 반드시 포함한다.
운영 상한500은 모든 구간과 두 극값을 포함하기에 충분하다. 별도 설정 상한이 작으면
극값을 우선하며1건 상한에서는 최저 별점만 보존할 수 있다.
구간 안에서는 작성 시각·리뷰 ID 순서를 기준으로 시점이 분산되도록 선택한다.
같은 입력은 같은 표본을 만들고 출력은 리뷰 ID 순서다. 중복이나 임의 점수 변경은 없다.

## 저장·무효화·조회

원본 전체 리뷰의 해시를 사용한다. 선택하지 않은 리뷰가 바뀌어도 결과는 stale로 전환한다.
입력 스냅샷에는 표본 정책 버전·상한·원본/선택 건수·별점 구간별 원본/선택 분포를 저장한다.
재시도는 같은 job ID와 저장된 표본을 사용한다. 상한이나 표본 정책이 바뀌면 새 작업을 만든다.
기존500건 이하의 완료 작업은 같은 입력·모델·정책이면 재사용한다.

analysis 응답의 review_count/input_review_count는 실제 분석한 건수다.
source_review_count와 sampled 및 sampling 메타데이터로 원본 전체 건수·표본 여부를 표시한다.
리뷰 페이지의 results에는 실제 분석한 리뷰만 포함한다. 비선택 리뷰의 점수를 만들지 않는다.
표본의 network 점수는 해당 표본 집합에 대한 결과이며 전체 리뷰 분석 결과로 취급하지 않는다.
공용 core/models.py는 변경하지 않고 작업 JSONB와 API 추가 필드로 표현한다.

## 운영

서버 AI_ANALYSIS_ENABLED=true를 설정하고 api/worker/analysis-worker/scheduler에 반영한다.
기존 리뷰는 crawler analysis-backfill로 예약하며 --force 없이 완료된 동일 입력을 재사용한다.
별도 분석 워커 하나가 순차 처리한다. 토큰은 기존 서버 설정을 사용하며 출력하지 않는다.
배포 직전 관측: 상품663개·리뷰25,956건,500건 초과 상품0개, 분석 done1건이다.
전체 예약과 자동 처리는 활성화하지만 예약된 전체 작업의 완료를 즉시 완료로 표시하지 않는다.

## 검증

500건 경계·희소 극값·별점 미제공·비례 할당·입력 순서 독립성과 중복 없는 재현성을 확인한다.
PostgreSQL에서500건 표본 전송·결과 저장·전체 입력 변경·정책 변경·기존 완료 재사용·
API 표본 메타데이터와 비선택 리뷰 페이지를 확인한다. 운영에서는 실제 작업 진행과 조회를 확인한다.
