# 크롤러 및 저장 개선

## 네이버 리뷰 미수신

최근7일 네이버 리뷰 실패128건은 리뷰 목록 미수신이며 상품에 양수 리뷰 수가 존재했다. locknlock:13781489400의 기존 코드를 읽기 전용으로 재현한 결과 기존 숫자 포함 탭 선택과 일반 리뷰 경로가 실제 화면의 숫자 없는 리뷰 탭·group-products/query-pages 경로를 놓쳤다.

숫자 없는 리뷰 탭을 우선 선택하고 숫자·괄호 포함 탭도 지원한다. 응답 URL은 쿼리 문자열을 제외한 경로로 비교하며 기존 및 묶음 경로만 허용한다. 묶음 응답은 productNo를 우선하고 없는 경우 originProductNo로 요청 상품과 비교한다. 묶음 응답의 식별값 없는 행은 저장하지 않는다. 작성자 식별값은 기존처럼 저장하지 않는다.

수정 코드를 같은 운영 환경에서 읽기 전용 실행하여 상품 리뷰 수1건·수집1건을 확인했다. 묶음 응답8건 중 요청 상품1건만 반환했다. 검증에서는 DB 저장·AI 요청·Backfill 제어를 하지 않았다. 아직 리뷰 탭 첫 페이지 수집이며 전체 페이지 수집을 구현한 것으로 해석하지 않는다.

## 리뷰 저장 최적화 (#110)

- 정규화·동일 ID 마지막 관측 선택 이후 500건씩 upsert한다. asyncpg 바인드 제한을 넘는 3,000건 입력도 저장 가능하다.
- 모든 배치는 기존 상품 잠금과 같은 트랜잭션을 사용한다. 중간 실패 또는 rollback 시 부분 저장을 남기지 않는다.
- 내용·별점·작성자·작성일·옵션·이미지·도움 수가 같으면 `updated_at`과 상품의 `analysis_input_hash`를 보존하고 `last_collected_at`만 갱신한다.
- 새 리뷰 또는 값 변경 시 분석 입력 캐시를 무효화한다. 도움 수만 변경된 경우도 보수적으로 무효화하되, 분석 예약 단계의 입력 해시 비교가 불필요한 재분석을 막는다.
- 기존 복합 기본키의 ON CONFLICT 경로를 유지하며 새로운 인덱스나 데이터 삭제를 요구하지 않는다.
- PostgreSQL 16 통합 테스트에서 별점 4.1의 동일 재관측, 변경 감지, 3,000건 분할 저장, 중복 ID 마지막 관측, 전체 rollback을 확인했다.

## 수집 실패와 재예약 (#111)

`collection_jobs.failure_kind`와 `retry_after`를 추가한다. 최신 종료 작업이 실패한 경우에만 정기 재예약을 미룬다. 수동 요청은 기존과 같이 큐에 넣을 수 있으며, 이후 성공하면 과거 대기는 적용하지 않고 연속 실패 횟수를 초기화한다.

기본 설정 `SCHEDULE_FAILURE_COOLDOWN_SECONDS=21600`에서 첫 실패 대기는 다음과 같다.

| 원인 | 첫 대기 |
| --- | --- |
| 접근 차단·요청 제한 | 6시간 |
| 시간 초과·네트워크/서버 오류·DB 저장 실패 | 10분 |
| 응답 파싱·기타 오류 | 1시간 |
| 인증 설정 필요·미지원·404/410 | 24시간 |

연속 실패마다 대기를 두 배로 늘리되 최대 24시간으로 제한한다. 위 설정이 0이면 새 실패의 대기를 끈다. lease 시도 상한 초과는 시간 초과로 기록하고 1시간 대기한다. 기존 미분류 이력은 기존 고정 대기 설정을 유지한다.

- 정상 리뷰 0건은 성공이며 실패·차단 집계에 포함하지 않는다.
- 명확한 접근 차단 예외는 상품 요청 직후 수집을 끝내고 추가 리뷰 요청을 하지 않는다.
- `/status`는 상품별 최신 실패를 원인별로 집계하고 대기 상품 수·가장 이른 재시도 가능 시각을 보여준다. 이는 실행 확정 시각이 아니며 TTL, 큐 여유, Backfill 수집 중지 설정도 적용된다.
- 원본 오류·리뷰 본문·작성자·토큰은 운영 집계에 포함하지 않는다.
- 마이그레이션 `c79fa18d2e60`은 기존 데이터를 삭제하지 않고 nullable 열 두 개와 상품별 이력 조회 인덱스를 추가한다.
